# Framework de Trabajo del Área Digital
## Versión 0.3 — Documento maestro de trabajo

**Estado:** Borrador en construcción  
**Propósito:** Documento interno de trabajo para estructurar, discutir y evolucionar la metodología del área digital.  
**Naturaleza:** Este documento no busca imponer una única forma de trabajar. Busca establecer criterios, estructuras, puntos de control, responsabilidades, mecanismos de análisis y rutas de reacción comunes.

---

# 0. Contexto y punto de partida

El área digital parte de una fortaleza importante: existe una alta capacidad operativa, agilidad para responder, disposición para probar y un equipo con experiencia suficiente para resolver situaciones complejas.

Hoy una parte importante de esa capacidad depende del criterio individual de quienes participan en las cuentas. Los problemas se resuelven, las campañas se optimizan y las situaciones inesperadas se atienden, pero muchas veces el conocimiento detrás de esas decisiones queda en:

- La experiencia de cada persona.
- Conversaciones internas.
- Chats.
- Reuniones.
- Interpretaciones particulares.
- Formas individuales de organizar el trabajo.

Esto no significa que el método actual no funcione. Al contrario, funciona precisamente porque existe talento y experiencia.

El reto es diferente:

> **¿Cómo convertimos esa capacidad individual en una capacidad colectiva sin volver burocrática la operación?**

El framework busca resolver ese reto.

La intención no es definir cómo debe pensar cada Planner ni cómo debe optimizar cada especialista de Performance. La intención es establecer:

- Qué preguntas mínimas debemos hacer.
- Qué información debemos revisar.
- Qué controles no podemos omitir.
- Qué decisiones deben quedar documentadas.
- Cuándo una situación debe escalarse.
- Cómo deben conectarse las diferentes disciplinas.
- Cómo debe organizarse la información.
- Cómo convertimos los aprendizajes en nuevas capacidades del equipo.

---

# 1. Objetivo general del framework

Construir un sistema de trabajo para el área digital que permita:

1. Mantener la agilidad operativa actual.
2. Preservar la autonomía profesional de cada integrante.
3. Estandarizar criterios mínimos de trabajo.
4. Aumentar la capacidad estratégica del equipo.
5. Mejorar la conexión entre estrategia y ejecución.
6. Incorporar factores externos al análisis de resultados.
7. Conectar Paid Media con Data, CRM, SEO, Creatividad y negocio.
8. Detectar desviaciones antes de que se conviertan en problemas mayores.
9. Mejorar el seguimiento presupuestal.
10. Generar una forma común de reaccionar frente a situaciones recurrentes.
11. Documentar decisiones y aprendizajes.
12. Reducir dependencia de personas específicas.
13. Mejorar la trazabilidad de las cuentas.
14. Hacer que la información sea fácilmente entendible por el cliente.
15. Construir repositorios que funcionen como fuente única de verdad.

---

# 2. Principio rector

## No estandarizar el talento. Estandarizar los mínimos.

El framework no debería decirle a una persona exactamente cómo resolver cada situación.

Debe definir:

- Qué información debe considerar.
- Qué variables debe revisar.
- Qué criterios no puede ignorar.
- Qué riesgos debe validar.
- Qué puntos de control deben cumplirse.
- Qué debe quedar documentado.
- Cuándo debe involucrar a otra persona o área.
- Cuándo debe escalar.
- Qué significa que una situación quedó cerrada.

Cada integrante conserva libertad profesional dentro de ese marco.

# 3. Qué queremos evitar

Este framework debe evitar convertirse en:

- Un manual burocrático.
- Una lista de pasos que nadie consulta.
- Una obligación administrativa adicional sin valor.
- Un repositorio lleno de información duplicada.
- Un conjunto de documentos desactualizados.
- Una forma de quitar autonomía a los especialistas.
- Una estructura excesivamente compleja para el cliente.
- Un sistema que documente más de lo que ayuda a decidir.

## Regla práctica

Si un documento no ayuda a:

- decidir,
- ejecutar,
- controlar,
- comunicar,
- aprender,

probablemente no debería existir.

# 5. Cómo entendemos los resultados digitales

Uno de los cambios más importantes del framework es reconocer que los resultados no dependen exclusivamente de las plataformas de pauta.

## Modelo general

**Resultado digital = medios + creatividad + oferta + producto + experiencia + gestión comercial + medición + contexto**

Esto significa que Digital debe analizar más allá de:

- CPM.
- CPC.
- CTR.
- CPA.
- ROAS.
- CPL.

Los indicadores de plataforma siguen siendo fundamentales, pero no son suficientes para explicar el comportamiento del negocio.

# 9. Dirección Digital

## Propósito

Dirigir el sistema de trabajo del área y asegurar que operación, estrategia, control y aprendizaje funcionen de manera integrada.

## Responsabilidades

- Definir visión.
- Establecer estándares.
- Priorizar portafolio.
- Distribuir recursos.
- Resolver conflictos de prioridad.
- Liderar escalaciones.
- Validar riesgos relevantes.
- Facilitar integración entre disciplinas.
- Auditar procesos.
- Transferir aprendizajes entre cuentas.
- Desarrollar capacidades del equipo.
- Asegurar evolución del framework.

## No debería convertirse en

- Aprobador de cada campaña.
- Revisor de cada optimización.
- Punto obligatorio para todas las decisiones.
- Única fuente de criterio estratégico.

---

# 10. Planner Estratégico Digital

## Propósito

Conectar negocio, categoría, audiencia, contexto, canales y resultados para convertirlos en una ruta estratégica y accionable.

## Responsabilidades

- Entender el negocio.
- Entender categoría y competencia.
- Entender objetivos comerciales.
- Identificar variables externas.
- Construir hipótesis.
- Definir prioridades.
- Construir escenarios.
- Conectar Paid Media con otras disciplinas.
- Traducir información en acciones.
- Liderar briefs estratégicos.
- Interpretar resultados.
- Construir narrativa de resultados.
- Mantener radar de contexto.
- Coordinar necesidades con otras áreas.
- Detectar cuando el problema excede Paid Media.

## El Planner no debe

- Monopolizar la estrategia.
- Convertirse en un intermediario obligatorio.
- Ser la única persona que entiende el cliente.
- Entregar planes cerrados sin discusión con Performance.

---

# 11. Especialista de Performance / Trafficker

## Propósito

Diseñar, implementar, monitorear y optimizar sistemas de adquisición y conversión, aportando interpretación y criterio estratégico desde la operación.

## Responsabilidades

- Implementar campañas.
- Diseñar arquitecturas.
- Configurar objetivos.
- Gestionar inversión.
- Diseñar pruebas.
- Detectar anomalías.
- Monitorear KPIs.
- Documentar cambios.
- Proponer hipótesis.
- Identificar oportunidades.
- Evaluar audiencias.
- Analizar creatividad.
- Validar tracking.
- Relacionar medios con negocio.
- Escalar cuando el problema excede la plataforma.

## Evolución esperada del rol

No buscamos un ejecutor pasivo.

Buscamos un especialista capaz de decir:

> “La caída no parece originarse en medios. La entrega y el tráfico permanecen estables; la afectación empieza después del clic. Necesitamos revisar landing, tracking y comportamiento comercial.”

# 23. Proceso: Ciclo de campaña

## Valor

Garantizar que cada campaña tenga una justificación estratégica, presupuesto, activos, medición y criterio de éxito antes de entrar en plataforma.

## Activadores

- Inicio de mes.
- Nuevo periodo.
- Nueva campaña.
- Nueva promoción.
- Nuevo producto.
- Evento.
- Cambio de estrategia.
- Cambio importante de presupuesto.

## Flujo

**Contexto → Objetivo → Hipótesis → Presupuesto → Materiales → Implementación → QA → Activación → Monitoreo → Aprendizaje**

## Preguntas mínimas antes de lanzar

- ¿Qué hacemos?
- ¿Por qué?
- ¿Para quién?
- ¿Qué queremos lograr?
- ¿Cuánto invertimos?
- ¿Qué esperamos?
- ¿Cómo medimos?
- ¿Qué vamos a probar?
- ¿Qué podría afectar el resultado?
- ¿Qué hacemos si ocurre una desviación?

## Resultado esperado

Campaña:

- correctamente configurada,
- correctamente medida,
- documentada,
- con presupuesto definido,
- con KPI definido,
- con periodo inicial de monitoreo.

> “Necesitamos validar dos hipótesis de comunicación para mejorar adquisición en una audiencia determinada.”

- Objetivo.
- Audiencia.
- Barrera.
- Hipótesis.
- Mensaje.
- Oferta.
- Acción esperada.
- Aprendizaje previo.

## Nivel productivo

- Pieza.
- Formato.
- Plataforma.
- Dimensión.
- Cantidad.
- Fecha.
- Estado.
- Responsable.
- Link final.

# 25. Proceso: Implementación técnica y tracking

## Valor

Evitar que inversión entre en plataforma sin capacidad adecuada de medición.

## Flujo

**Requerimiento → Implementación → Validación → QA → Aprobación → Activación**

## Validaciones mínimas

- Landing correcta.
- URL correcta.
- Eventos.
- Conversión.
- Fuente.
- UTM.
- Pixel / etiqueta.
- Integraciones.
- CRM cuando aplique.
- Prueba real.
- Nomenclatura.
- Validación Data cuando aplique.

## Regla crítica

> Una campaña sin medición validada no está lista para lanzamiento.

---

# 26. Proceso: Seguimiento presupuestal

## Valor

Controlar consumo, anticipar desviaciones y proyectar el cierre de inversión.

El cuadro presupuestal no debe ser únicamente un registro de cuánto se gastó.

Debe responder:

- ¿Cuánto deberíamos llevar?
- ¿Cuánto llevamos?
- ¿Cuál es la desviación?
- ¿Cuánto queda?
- ¿Cuántos días quedan?
- ¿Qué ritmo necesitamos?
- ¿Cómo proyectamos cerrar?
- ¿Necesitamos intervenir?

# 28. Indicadores presupuestales

## Pacing

**Pacing = consumo actual / consumo esperado**

Interpretación:

- Cerca de 100%: consumo alineado.
- Menor al esperado: subconsumo.
- Mayor al esperado: sobreconsumo.

Los umbrales concretos se definirán posteriormente.

## Consumo diario requerido

**Presupuesto restante / días restantes**

Permite anticipar si el ritmo necesario es razonable.

## Proyección de cierre

Puede estimarse a partir de:

- Ritmo promedio actual.
- Ritmo reciente.
- Curva planificada.
- Eventos futuros.

---

# 29. Modelos de pacing

## 29.1 Lineal

Para campañas estables.

**Presupuesto esperado = presupuesto total × porcentaje del periodo transcurrido**

## 29.2 Planificado

Para campañas que no deben gastar de forma uniforme.

Ejemplo:

- Semana 1: 15%.
- Semana 2: 20%.
- Semana 3: 40%.
- Semana 4: 25%.

El sistema debe comparar contra la curva acordada, no contra una distribución lineal artificial.

# 30. Sistema de Alertas Digitales

## Valor

Detectar desviaciones antes de que generen impactos relevantes.

## Diferencial

El sistema no espera a que el cliente reporte un problema.

El equipo monitorea de forma proactiva el comportamiento de las cuentas.

# 31. Frecuencia de alertas

## Revisiones programadas

Dos veces por semana.

Objetivo:

- Identificar tendencias.
- Detectar desviaciones.
- Revisar KPIs.
- Revisar presupuesto.
- Revisar anomalías.
- Priorizar acciones.

## Alertas críticas

Se atienden inmediatamente.

No esperan al siguiente ciclo.

Ejemplos:

- Tracking caído.
- Cuenta suspendida.
- Conversión anormalmente en cero.
- Gasto acelerado.
- Presupuesto agotándose.
- URL incorrecta.
- Campaña sin entrega.
- Error técnico grave.

# 38. Etapa 4: hipótesis

Regla:

> No hacemos un cambio sin declarar qué creemos que estamos intentando corregir.

“El aumento de frecuencia y la caída de CTR sugieren saturación. Ampliaremos audiencia y renovaremos creatividad para validar si la causa corresponde a fatiga.”

# 44. Qué es un Playbook

Un Playbook responde:

> **¿Cómo reaccionamos ante una situación específica que requiere análisis, criterio y acción?**

No pretende ofrecer una respuesta automática.

Su función es asegurar que el equipo:

- Detecte correctamente.
- Analice.
- Contextualice.
- Diagnostique.
- Actúe.
- Escale.
- Comunique.
- Aprenda.

---

# 45. Flujo estándar de un Playbook

**Alerta → Activación → Severidad → Análisis y entendimiento → Primera respuesta → Diagnóstico → Hipótesis → Acción → Escalamiento → Comunicación → Validación → Cierre → Aprendizaje**

Este flujo debería ser consistente en todos los playbooks.

---

# 46. Ficha estándar de Playbook

Cada playbook deberá contener las siguientes secciones.

---

## 46.1 Nombre

Debe describir la situación.

Ejemplos:

- Caída significativa de performance.
- Desviación presupuestal.
- Falla de tracking.
- Baja calidad de leads.
- Bloqueo de cuenta.
- Campaña sin entrega.
- Error de implementación.

---

## 46.2 Propósito

Explicar:

- Qué problema busca controlar.
- Qué riesgo busca reducir.
- Qué resultado busca garantizar.

---

## 46.3 Cuándo se activa

Definir señales observables.

Ejemplos:

- Incremento relevante del CPA.
- Caída de conversiones.
- Desviación presupuestal.
- Cambio abrupto frente a línea base.
- Reporte comercial.
- Tracking en cero.
- Error de cuenta.
- Alerta automática.

La activación debe ser verificable.

## S1 — Crítica

Existe riesgo inmediato sobre:

- Dinero.
- Reputación.
- Datos.
- Cuenta.
- Continuidad.
- Resultado comercial.

- Contención.
- Escalamiento.
- Comunicación rápida.

Desviación manejable dentro de operación normal.

# 52. Qué sí hacer en un Playbook

- Validar datos.
- Revisar contexto.
- Formular hipótesis.
- Separar síntoma de causa.
- Priorizar riesgos.
- Hacer cambios controlados.
- Definir observación.
- Documentar.
- Comunicar.
- Escalar.
- Revisar impactos comerciales.
- Ajustar proyecciones si cambian los supuestos.

---

# 53. Qué no hacer en un Playbook

- No reaccionar a ruido diario.
- No modificar todo simultáneamente.
- No asumir que el problema es la plataforma.
- No atribuir causalidad sin evidencia.
- No ocultar alertas relevantes.
- No esperar una solución completa para comunicar un riesgo.
- No cambiar proyecciones sin revisar supuestos.
- No dejar decisiones importantes solo en chat.
- No cerrar sin documentar aprendizaje.

# 54. Escalamiento

## Performance → Planner

Cuando:

- La causa supera Paid Media.
- Se necesita cambio estratégico.
- Cambian supuestos.
- Existe impacto importante.
- Se requiere otra disciplina.

## Planner → Dirección Digital

Cuando:

- Existe riesgo importante de inversión.
- Se afecta relación con cliente.
- Cambian compromisos.
- Existe riesgo reputacional.
- Se requiere priorización especial.

## Digital → Data

Cuando:

- Existen dudas sobre datos.
- Hay inconsistencias.
- Se necesita cruce.

## Digital → CRM / Comercial

Cuando:

- El problema está en calidad.
- Contactabilidad.
- Venta.
- Capacidad.

## Digital → Creatividad

Cuando:

- Existe fatiga.
- Falta relevancia.
- Se necesita nueva hipótesis.

## Digital → Técnica / Tracking

Cuando:

- Existe error de medición.
- Landing.
- Integración.
- Etiquetado.

# 55. Comunicación de una alerta o incidente

Toda comunicación debe seguir esta estructura:

**Situación → Impacto → Contexto → Hipótesis → Acción → Próxima actualización**

## Ejemplo

Al mismo tiempo terminó un evento que concentraba demanda en la categoría, por lo que estamos evaluando cuánto corresponde a una normalización del mercado y cuánto puede estar relacionado con la conversión posterior al clic. Estamos validando landing, tracking y comportamiento comercial. La siguiente actualización incluirá diagnóstico y acciones recomendadas.

> El asunto debe permitir identificar cliente y contenido sin abrir el correo.

# 74. Jerarquía de campañas

```text
Cliente
└── Ruta / iniciativa estratégica
    └── Campaña
        └── Audiencia / grupo de anuncios
            └── Anuncio / activo
```

La ruta estratégica permite agrupar campañas relacionadas con una intención común.

# 75. Nomenclatura de campaña

## Campaña

**[Objetivo] | [Iniciativa] | [Mercado] | [Periodo]**

Ejemplos:

- Conversión | Reactivación post-Mundial | CO | Ago-Sep 2026
- Adquisición | Bono de bienvenida | CO | Always-on
- Reconocimiento | Lanzamiento de producto | Bogotá | Sep 2026

---

# 76. Nomenclatura de audiencias

**[Tipo] | [Segmento] | [Condición]**

Ejemplos:

- Prospección | Fútbol | Amplia
- Remarketing | Visitantes web | 30 días
- CRM | Usuarios inactivos | 90 días
- Similar | Clientes alto valor | 1%

---

# 77. Nomenclatura de anuncios

**[Formato] | [Ángulo / mensaje] | [Versión]**

Ejemplos:

- Video | Bono de bienvenida | V01
- Estático | Mejores cuotas | V02
- Carrusel | Partidos de la semana | V01

---

# 78. Código interno de campañas

No se utilizará un código interno adicional.

## Razón

La nomenclatura de campaña ya debe permitir:

- Identificación.
- Lectura interna.
- Lectura del cliente.
- Organización.

Agregar un segundo código produciría una capa administrativa adicional sin valor suficiente.

# 81. Reglas del sistema documental

1. Una sola estrategia vigente.
2. Toda proyección declara supuestos.
3. Toda prueba tiene hipótesis.
4. Toda prueba tiene conclusión.
5. Toda decisión relevante queda documentada.
6. Todo informe genera acciones.
7. Toda alerta relevante tiene seguimiento.
8. Todo Playbook debe cerrar.
9. Toda página tiene responsable.
10. Documentos sustituidos salen de navegación activa.
11. El nombre identifica; los metadatos describen.
12. Lo que solo existe en chat todavía no está documentado.
13. Todo diagnóstico considera contexto.
14. Todo cambio importante debe poder explicarse.
15. Todo aprendizaje importante debe ser reutilizable.

# 84. Criterio de éxito del framework

El éxito no se medirá por la cantidad de documentos creados.

Se medirá por:

- Menor dependencia de individuos.
- Mayor claridad de decisiones.
- Menos errores repetidos.
- Mayor capacidad de anticipación.
- Mejor lectura estratégica.
- Mejor comunicación con clientes.
- Mayor integración entre áreas.
- Mejor control presupuestal.
- Respuesta más rápida a anomalías.
- Mayor capacidad de aprendizaje.
- Mayor trazabilidad.
- Mayor facilidad de incorporación de nuevos integrantes.

# 85. Principio final

> **El área digital no administra únicamente plataformas. Interpreta la relación entre negocio, audiencia, creatividad, medios, datos y contexto; convierte esa lectura en hipótesis, acciones, medición y aprendizaje.**

El framework existe para que esa capacidad no dependa únicamente de quién esté sentado frente a la cuenta, sino que se convierta en una capacidad permanente del equipo.
